# المرحلة 0 — خط أساس إعادة تصميم شاشة POS

## الحالة

- المستودع: `Sham4753/kashir-alqaisar-pos`، أساس العمل `main` عند commit `c9f1a6b`.
- فرع هذه المرحلة: `phase-0-pos-baseline`.
- هذه المرحلة تدقيق واختبار مرجعي فقط؛ لا تغيّر HTML أو CSS أو JavaScript أو API.

## ما ظهر في خط الأساس

1. عند `max-width: 1080px` يضع `app/pos-modern.css` لوحة الطلب بعد الكتالوج، كما تتراكم قواعد لاحقة متعارضة لتغيير الأعمدة والدرج وشريط الفئات.
2. ملف `pos-modern.css` يحتوي على سلسلة إضافات متأخرة متداخلة؛ وتُحمّل صفحة POS أربع طبقات مرئية من `design-system.css` و`pos-modern.css` و`palette-v3.css` و`theme.css`، مع تكرار متغيرات القالب وتجاوزات `!important` في طبقة الثيم.
3. الفئات تُعرض حاليًا كمصفوفة متعددة الصفوف لا كشريط أفقي؛ وبلاطات الأصناف كبيرة نسبيًا، وملاحظة الصنف ظاهرة كحقل نص مستقل.
4. إجمالي الفاتورة معروض كسطرين متطابقين (المجموع الفرعي والإجمالي)، ولا يوجد شريط سفلي يفتح درج السلة على الأجهزة الصغيرة.
5. زر نوع الطلب يعرض «توصيل» في حين أن قيمة النوع وواجهات النظام الأخرى تستخدم «ديليفري». كما تعرض وصلة الدليفري داخل الشريط الجانبي تسمية «التوصيل».
6. قفل الشاشة، تحديث العملات، معاملات `/api/orders` وحالات الطباعة موجودة في JavaScript الحالي؛ يجب أن تبقى سلوكياتها دون تغيير عند تعديل العرض.

## اختبارات خط الأساس

- `python3 -m unittest discover -s tests -p 'test_pos_layout_css.py' -v` — ناجح: 2 اختبار.
- `python3 -m unittest discover -s tests -p 'test_theme_palette.py' -v` — ناجح: 6 اختبارات.
- `node tests/verify_frontend.mjs` — ناجح: «الواجهة سليمة؛ تحويل العملة والخصائص الأساسية تحققت.»

لم يُجرَ اختبار بصري بعد؛ لقطات المقاسات `1366×768` و`1024×768` و`390×844` مطلوبة عند اكتمال المرحلة 1. ولم يُجر اختبار على جهاز Windows أو طابعة فعلية.

## ضوابط القبول للمرحلة التالية

- الإبقاء على مفاتيح DOM التي تعتمد عليها JavaScript ومسارات `/api` ومنطق البيع والصلاحيات والقفل والعملة والطباعة ورسائل فشل الطابعة.
- واجهة كاشير مهيأة للمس: شريط تشغيل بالأيقونات، عدادات صغيرة، فئات أفقية ملونة، بطاقات أصناف مضغوطة بأهداف لمس لا تقل عن 48px، وملاحظة اختيارية خلف أيقونة.
- سلة مختصرة بإجمالي واحد وزر دفع رئيسي ثابت؛ وشريط سفلي يفتح درج السلة في التابلت والجوال بدل إلحاق السلة بأسفل الكتالوج.
- توحيد تسمية نوع الطلب إلى «ديليفري» ومصدر الألوان إلى tokens مشتركة واضحة، مع اختبارات تصميم تمنع عودة التجاوزات المتراكمة.
- اختبار الواجهة على المقاسات الثلاثة المذكورة وتوثيق ما لم يُختبر ماديًا.

## خارج النطاق الآن

المرحلة 5 (توجيه الطباعة حسب القسم) مؤجلة. قبل تنفيذها يجب سؤال المالك عن أسماء الأقسام وعدد الطابعات ونوع كل طابعة (USB أو شبكة) واسمها أو عنوان `IP:port` وعرض الورق. لن تُجرَ تغييرات للطباعة حسب القسم أو تذاكرها قبل تلقي هذه المعلومات واختبار الأجهزة الفعلية.
