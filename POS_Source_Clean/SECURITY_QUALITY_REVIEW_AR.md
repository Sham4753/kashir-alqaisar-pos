# مراجعة الجودة والأمان — كاشير القيصر

## نطاق المراجعة

شملت المراجعة واجهات الكاشير وتطبيق النادل، النصوص والملصقات، الصلاحيات، مسارات API، التخزين المحلي، التصدير، الاعتماديات، الاختبارات، وملفات CI. لم تُستخدم بيانات مطعم حقيقية، ولم يُختبر العتاد الفعلي من بيئة Linux.

## الإصلاحات المنفذة

| المجال | الإجراء | الحالة |
|---|---|---|
| النصوص والمظهر | إزالة الإيموجيات من النصوص المرئية في واجهات الكاشير، واستبدال رموز الاتصال بعبارات واضحة، وإصلاح مكوّن التحية في تطبيق النادل | منفذ ومفحوص |
| سلامة JavaScript | إصلاح دالة الأيقونات التي تضررت من تنظيف الرموز، ثم تشغيل `node --check` لكل ملفات JavaScript المستقلة | ناجح |
| حقن HTML | استخدام `escape` لأسماء المخزون ومحطات المطبخ قبل إدخالها في لوحة المدير، مع تحويل الأرقام إلى `Number` | منفذ |
| التخزين الذري | التحقق من `fsync` ثم `os.replace` في `atomic_write_json`، مع حذف الملف المؤقت عند الفشل | موجود في المنتج |
| الاعتماديات | تحديث حزم Expo إلى أحدث patch متوافق مع SDK 54، مع إبقاء React Native وExpo ضمن خط التوافق نفسه | منفذ |
| CI | إضافة Workflow للكاشير وWorkflow لتطبيق النادل لفحص القفل، TypeScript، الاختبارات، lint، الصياغة وسياسة الملفات الحساسة | منفذ |

## نتيجة الاعتماديات

أظهر `pnpm audit` بعد تحديث Expo بقاء ثغرات عابرة، منها `tar` و`shell-quote` داخل أدوات Expo/React Native. لذلك لا يُقال إن المشروع خالٍ من الثغرات. مسار المعالجة الصحيح هو ترقية خط Expo/React Native عندما تتوفر نسخة متوافقة تعالجها، أو قبول استثناء موثق لأن هذه الحزم أدوات بناء محلية وليست واجهة تشغيل POS على الإنترنت. لا تُستخدم ترقيات `force` أو overrides غير مدعومة.

## التحقق المطلوب قبل الإنتاج

يجب تشغيل CI في GitHub بعد رفع الملفات، وإعادة تنفيذ اختبار القبول على خزنة مؤقتة، ثم اختبار شاشة Windows والطابعة والدرج وقارئ الباركود والهاتف داخل شبكة المطعم. كما يجب اختبار قيم تحتوي على HTML وعلامات اقتباس في أسماء الأصناف والعملاء والملاحظات، والتأكد من عدم ظهورها كعناصر HTML.

## خارطة الطريق التقنية

| الأولوية | القرار المقترح |
|---|---|
| P0 | معالجة تبعيات Expo العابرة عند صدور patch متوافق، وتفعيل فشل CI عند الثغرات الحرجة بعد التحقق من أثرها |
| P0 | اعتماد اختبار نسخ احتياطي واستعادة فعلي مع إغلاق آمن للوردية |
| P1 | إضافة اختبارات متصفح آلية لمسارات البيع والصلاحيات وتطبيق escape على كل واجهة تعتمد innerHTML |
| P1 | فصل event listeners عن `onclick` في الصفحات القديمة تدريجيًا |
| P2 | تقسيم الخادم إلى وحدات: auth، sales، inventory، finance، printing، waiter LAN |
| P2 | إضافة مراقبة إصدارات دورية للـlock files ونتائج CI دون تحديث تلقائي غير مراقب |

> لا تعتبر نتائج CI أو الفحوص الآلية بديلًا عن اختبار Windows والطابعات والشبكة والهاتف فعليًا.
